## 0. Phase 3 の主張が成立していなかった理由

Phase 3 は「semantic は raw より 20〜25 dB 強い」と結論していた。その比較には
**ペイロード情報量の非対称**があった。

| | 1メッセージあたり |
|---|---:|
| 交渉メッセージの情報量（共有プール既知でのオファー index + アクション） | **6.1 ビット** |
| `TextAgent` が実際にチャネルへ流していた量 | **約 600〜1350 ビット** |

[baseline_agent.py:67](../airComp/agents/baseline_agent.py#L67) が送っていたのは
**LLM の生成テキスト丸ごと** — 前置きの散文も、`include_rationale: True` による自由文の
`"message"` フィールドも含む。100〜200 倍の水増しであり、+10 dB の崖はこれだけで説明がつく
（BER 7.8e-4 × 650 ビット → 無傷確率 0.60。6.1 ビットなら 0.995）。

加えて `raw` と `arq` は**どちらも誤り訂正を持たない**（`arq` は CRC-8 で検出して捨てるだけ）。
実運用のデジタルリンクは必ず FEC を持つ。

そこで公平な基準線を2つ追加した。

| パイプライン | ペイロード | チャネル使用数 |
|---|---|---:|
| `raw` / `arq` | LLM 生成テキスト全文 | 約 650〜1350 |
| `compact` | オファーを 8 ビットに源符号化 | 8 |
| **`compact_fec`** | 同じ 8 ビット + Hamming(7,4) | **16** |
| `semantic` | k=16 のアナログ潜在ベクトル | **16** |

**`compact_fec` と `semantic` はチャネル使用数が完全に一致し、実数次元あたりの SNR も同一。**
これが唯一 apples-to-apples な比較。生成部は `TextAgent` と同一関数を使うので
（[compact_agent.py](../airComp/agents/compact_agent.py)、テストで prompt 列の一致を固定）、
違いはワイヤ上のものだけ。

符号器は `pool` を条件に使うが、これは公開情報であり、semantic デコーダの
`pool_to_mask` が使うのと同じ情報。片側だけの優位ではない。

## 1. 主結果 — 床と天井で正規化した比較

生の合意率は比較できない。パイプラインごとに 0 も 1 も違うため。

- **床** = チャネルが何も運ばないとき（−60 dB 実測）の値。`SemanticDecoder` は常に構造的に
  妥当なオファーを出すので、両エージェントの事前分布が偶然一致して **0.48** に達する。
  デジタル側は復号失敗が暗黙の REJECT になるのでほぼ 0
- **天井** = チャネルがほぼ無損失なとき（+40 dB 実測）の値。LLM が使えるオファーを出せない
  ことがあるので 1.0 未満。`CompactAgent` は符号化のため自前 JSON を解釈する必要があり、
  `SemanticAgent` は隠れ状態を使うので解釈しない。この差が天井に出る

比較可能な量は **(p − 床) / (天井 − 床)** ＝ 到達可能レンジのうちチャネルが実際に届けた割合。
計算は [airComp/eval/normalize.py](../airComp/eval/normalize.py)（テスト済み）。

| | 床 | 天井 | −20 | −15 | −10 | −5 | 0 | +5 | +10 | +15 | +20 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| semantic | 0.48 | 0.98 | 0.44 | 0.52 | 0.68 | 0.92 | 1.04 | 0.96 | 1.04 | 1.04 | 1.00 |
| compact | 0.02 | 0.94 | 0.07 | 0.04 | 0.04 | 0.09 | 0.28 | 0.63 | 0.93 | 0.76 | 0.91 |
| compact_fec | 0.06 | 0.90 | −0.07 | −0.07 | −0.05 | 0.12 | 0.48 | 0.86 | 1.05 | 0.98 | 1.02 |
| compact（ターン数同一） | 0.08 | 0.94 | 0.05 | 0.09 | 0.07 | 0.19 | 0.47 | 0.72 | 0.95 | 1.02 | 1.00 |
| **compact_fec（同上）** | 0.10 | 0.94 | −0.05 | 0.00 | 0.12 | 0.24 | 0.67 | 0.88 | 0.98 | 0.83 | 0.90 |

### 実効 SNR 利得

| 基準線 | 正規化 0.5 | 正規化 0.9 |
|---|---:|---:|
| raw / arq（旧主張の相手） | — | 20〜25 dB |
| compact | 19.4 dB | 14.8 dB |
| compact_fec | 16.6 dB | 11.5 dB |
| compact（ターン数同一） | 16.9 dB | 14.3 dB |
| **compact_fec（最強の公平基準線）** | **14.3 dB** | **11.4 dB** |

**主張すべき数字は 11〜14 dB。**

## 2. 利得の3段分解

| 段 | 分離される要因 | 効果 |
|---|---|---|
| raw → compact | **ソース符号化**（約1000 → 8 ビット） | +10 dB で 0.28 → 0.88。**単独では最大** |
| compact → compact_fec | **誤り訂正** | 0 dB で 0.28 → 0.46。約 3 dB 相当 |
| compact_fec → semantic | **アナログ潜在表現** ← 本研究の主張 | **11〜14 dB** |

**Phase 3 の 20〜25 dB のうち、半分以上はソース符号化と FEC の欠如だった。**
この分解を出さずに元の数字を示すのは不誠実。

理論値とも整合する。Hamming(7,4)×2 のフレーム到達率は 0 dB で 0.479、+5 dB で 0.948、
2メッセージ揃う確率が 0.230 / 0.899 — 実測の合意率 0.46 / 0.78 と同じ形。

### 機序 — アナログ潜在表現の局所性

主張の中身は「小さな雑音は近いオファーに落ちる」こと。§6 がこれを実測している
（+20 dB で完全一致 0.832 → −10 dB で 0.646 と*連続的に*劣化しつつ、タスクは成立）。

ただし **ビットインデックス側にも部分的な局所性がある** — 辞書順インデックスは混合基数の
位置符号なので、桁の下位ビットが反転すれば1品目が1個ずれるだけ。実測（全プール形状の
全実行可能オファー、単一インデックスビット反転）:

| 反転結果 | 割合 |
|---|---:|
| 実行可能集合の外 → 暗黙の REJECT | **24.5%** |
| L1 距離 1（軽微） | 26.8% |
| L1 距離 2 以上 | 48.7% |

つまり compact は藁人形ではなく、部分的には緩やかに劣化する。差を生んでいるのは
**「符号帳から落ちる 1/4」であって「局所性がゼロであること」ではない。**
計画段階の想定は間違っており、実測で訂正した。

## 3. SNR の定義が両チャネルで一致していることの確認

これはフェアネスの根幹なので実測した。

```
digital BPSK: 実測 BER と教科書2種の照合
  SNR    実測      Q(sqrt(S))   Q(sqrt(2S))
   +0  1.59e-01    1.59e-01     7.86e-02
   +5  3.77e-02    3.77e-02     5.95e-03
  +10  7.82e-04    7.83e-04     3.87e-06

実数次元あたりの 信号電力/雑音電力:
  analog  公称 +10 dB -> 実測 +10.00 dB
  digital 公称 +10 dB -> 実測 +10.00 dB
```

**両チャネルとも「実数次元あたりの信号電力 / 雑音分散」が公称値どおり。** BPSK シンボルと潜在
ベクトルの各成分が同じ次元あたり SNR を受け取っており、比較は成立している。

⚠ **教科書の BPSK 曲線とは 3 dB ずれる。** 本実装の BER は `Q(sqrt(SNR))` で、教科書の
`Q(sqrt(2·Eb/N0))` ではない（雑音分散の取り方の違い）。査読者は必ず標準曲線と照合するので、
「ベースラインを不当に痛めつけている」と誤解される前にこれを明示すること。両チャネルで
同一の定義を使っている以上、比較の公平性は損なわれていない。

崖の位置もこれで説明がつく: +10 dB で BER 7.8e-4、1メッセージ約650ビット →
無傷な確率 (1−7.8e-4)^650 ≈ 0.60、1エピソードに約2メッセージ必要 → 0.36。実測 0.28 と整合。

## 4. 実機とシミュレーションの一致 — DSP チェーンの検証

対シード設計（`int(snr_db*10_000) + 1_000_000` が両者で一致）なので、系統的なズレがあれば
物理現象ではなくバグ。

| 要求 SNR | 実測 SNR | sim 合意率 | 実機 合意率 | 差 |
|---:|---:|---:|---:|---:|
| −10 | −9.59 | 0.82 | 0.87 | +0.05 |
| −5 | −4.33 | 0.94 | 1.00 | +0.06 |
| 0 | −0.67 | 1.00 | 1.00 | 0.00 |
| +5 | **+6.36** | 0.96 | 1.00 | +0.04 |
| +10 | +9.83 | 1.00 | 1.00 | 0.00 |
| +15 | +14.70 | 1.00 | 0.93 | −0.07 |
| +20 | +20.32 | 0.98 | 1.00 | +0.02 |

**系統的なズレは無い。** 平均差 +0.014、最大 |差| 0.07。実機は 15 エピソードなので
1 エピソード = 0.067 であり、**すべてのズレが1エピソード以内**。DSP チェーン
（RRC 整形、IF オフセット、ZC プリアンブル、パイロット、ゼロフォーシング等化、SNR 推定）は
シミュレーションのアナログチャネルを正しく再現している。

バースト欠落率は全点 **0%**、RX 警告ゼロ、リトライ 0%。

⚠ **+5 dB 点だけ要求と実測が 1.36 dB ずれており、1 dB 基準を外している**（他6点は 0.17〜0.67 dB）。
較正テーブルの粒度による。図では実測 SNR の位置に描いてあるので結論には影響しないが、
較正点を増やせば解消する。

### デジタル経路も同じく一致する（2026-08-19）

`compact_fec` も実機で走らせた（`hwlab/results/sdr_sweep_compact.json`、7点 × 15）。
**16 ビットの符号化フレームは 16 実数次元 = 8 複素シンボルで、k=16 の潜在ベクトルと
まったく同じバーストに載る** — `n_data` も送信電力も変えていない。

| 要求 SNR | 実測 SNR | 実機 | sim（実測 SNR に内挿） | 差 | z |
|---:|---:|---:|---:|---:|---:|
| −10 | −9.90 | 0.00 | 0.02 | −0.02 | −0.7 |
| −5 | −4.22 | 0.07 | 0.21 | −0.14 | −1.6 |
| 0 | −0.68 | 0.33 | 0.42 | −0.09 | −0.6 |
| +5 | +6.08 | 0.93 | 0.81 | +0.12 | +1.4 |
| +10 | +9.78 | 0.87 | 0.93 | −0.07 | −0.7 |
| +15 | +14.74 | 0.87 | 0.88 | −0.02 | −0.2 |
| +20 | +20.16 | 0.87 | 0.92 | −0.05 | −0.6 |

**χ² = 6.3（7 自由度、期待値 ≈ 7）。** ばらつきはサンプリング雑音そのもので、
系統的なズレは無い（平均差 −0.038、最大 |z| = 1.6）。バースト欠落 0%、リトライ 0%、
RX 警告ゼロ。

semantic より散らばりが大きい（最大 |差| 0.14 vs 0.07）のはバグではなく分散。
実機 n=15 での標準誤差は p≈0.5 で 0.13、p≈0.9 で 0.08。semantic の実機点はほぼ全て
p≈1.0 に張り付いていて誤差が縮んでいたのに対し、compact_fec は遷移域のど真ん中を
通るので誤差が最大になる。

**SNR 規約の検証**（`hwlab/tests/test_sdr_digital.py`）— アナログ経路に対する
`test_mapping.py` のデジタル版。RF ビット経路の実測 BER を、リンクが実際に届けた SNR に
対して照合する:

| 実測 SNR | 実測 BER | `Q(√S)` | `Q(√2S)` | 比 |
|---:|---:|---:|---:|---:|
| −9.98 | 0.3812 | 0.3757 | 0.3270 | 1.01 |
| −2.34 | 0.2338 | 0.2224 | 0.1400 | 1.05 |
| +5.53 | 0.0306 | 0.0293 | 0.0037 | 1.04 |

**`Q(√S)` と 1〜5% で一致し、教科書の `Q(√2S)` は棄却される。** §3 と同じ規約が
実機デジタル経路でも成立している。テストは「この許容幅では教科書側も通ってしまう」場合に
落ちる第二のアサーションを持つので、後から緩められない。

⚠ **要求 SNR は較正テーブル経由でしか効かない。** `SDRAnalogChannel` の docstring どおり
`snr_db` は*要求*であり、実 SNR は利得と減衰で決まる。BER の検定は必ず**実測 SNR に対して**
行うこと（要求値に対して検定して全点が同じ値に張り付き、それで気づいた）。

## 5. 帯域の公平性

**Phase 4 でこの節の役割は大きく縮んだ。** `compact_fec` は semantic とチャネル使用数が
一致しているので、帯域は比較の交絡ではなくなった。以下は記録として残す。

### (a) 生のペイロードとチャネル使用数

| | 1メッセージのペイロード | 1メッセージのチャネル使用数 |
|---|---|---:|
| raw / arq | LLM 生成テキスト全文、約 650〜1350 ビット | 650〜1350 |
| compact | オファー 8 ビット | 8 |
| **compact_fec** | 同じ 8 ビット + Hamming(7,4) | **16** |
| **semantic** | k=16 の実数潜在ベクトル | **16** |

**compact_fec と semantic は完全に同一。** §1 の 11〜14 dB は帯域差では説明できない。

raw / arq のペイポードが SNR で変わるのは、低 SNR では早期終了してターン数が減るため。

### (b) Shannon 等価ビット（`k · 0.5·log2(1+SNR)`）

| SNR | −10 | −5 | 0 | +5 | +10 | +15 | +20 |
|---|---:|---:|---:|---:|---:|---:|---:|
| semantic 等価ビット/エピソード | 2.4 | 6.3 | 16.0 | 32.9 | 55.4 | 80.4 | 106.5 |

⚠ **この数字の読み方に注意。** −15 dB では 1 エピソードあたり 0.83 ビットしか通らないのに
合意率 0.74 が出る。オファーの無条件エントロピーは 6.1 ビットなので、1ビット未満で
交渉が妥結するはずがない。§9 のとおり、その領域の値はほぼ床である。

### (c) 実機の物理コスト（ここは semantic に不利）

```
data_symbols: 8   overhead_symbols: 863   total: 871   (99.1% がオーバーヘッド)
内訳: プリアンブル 511 + パイロット 32 + ガード 320
burst_duration: 8.71 ms   occupied_bandwidth: 135 kHz
```

同期のためのフレーミングコストで、JSCC の主張とは独立。**compact_fec を実機で送っても
同じ 871 シンボルがかかる**ので、これも比較の交絡ではない（ただし実機では compact 側を
まだ走らせていない — §8）。「16 シンボルで済む」という主張をするときは、この 871 を
併記しないと誤解を生む。

## 6. デコーダは本当にチャネルを使っているか

タスク指標が平坦なとき、「頑健」と「入力を無視して事前分布を出している」は区別がつかない。
`python evaluate.py decoder-check --checkpoint checkpoints/jscc_dml.pt --dataset data/jscc_dataset_dml.pt`

```
      条件      完全一致  項目別  アクション
 ノイズ無し       0.826   0.917   1.000
  SNR -10 dB      0.646   0.766   0.815
  SNR +20 dB      0.832   0.917   1.000
 純ノイズ         0.365   0.475   0.463
 ゼロ入力         0.495   0.553   0.501
 最頻値の定数     0.525   0.553      -

PASS: 信号 0.836 / ノイズ・ゼロ床 0.495 / 最頻値定数 0.525
```

**デコーダは確かにチャネル出力を使っている。** さらにオファー再現のレベルでは
**きちんと劣化している**（+20 dB で 0.832 → −10 dB で 0.646、アクション精度 1.000 → 0.815）。

つまり平坦なのは通信が完璧だからではなく、**交渉タスクが 20〜25% のオファー誤りを吸収する**から。
「緩やかな劣化」を主張するときは、タスク指標だけでなくこの再現精度を併記すること。

⚠ この診断は学習データ 935 件で測っているので絶対値は楽観的。ただし同じデータで純ノイズが
0.365 に落ちる以上、入力依存性の結論は変わらない。

## 7. 明示しておくべき非対称性

CLAUDE.md の方針（情報量の非対称は文書化するか対称化する）に従い、残っているものを列挙する。
**Phase 4 で 2 つは対称化された。**

### 対称化済み

1. ~~**ペイロード情報量**~~ — 約 1000 ビット vs 16 実数だった。`compact_fec` が
   チャネル使用数を 16 に揃えたことで解消（§0）
2. ~~**誤り訂正の有無**~~ — `raw`/`arq` は FEC を持たなかった。`compact_fec` の
   Hamming(7,4) で解消

### 残っている（semantic 有利）

3. **デコーダは実行可能オファーの masked prior を持つ**（`pool_to_mask`）。ただし
   `offer_codec` も同じ `pool` を条件に使うので、compact との比較では対称
4. **送信側 JSON がパース不能でも semantic は動く。** 隠れ状態は生成さえされればプールできる。
   `CompactAgent` は符号化のため自前 JSON を解釈する必要があるので、この失敗モードを継承する。
   **これは §1 の天井差（compact 0.94 / semantic 0.98）として定量済み**で、正規化で除去される
5. **失敗したときの退化先が違う。** semantic は事前分布（床 0.48）に、デジタル側は拒否
   （床 0.02〜0.10）に退化する。**正規化はこれを除去する**が、除去してよいかは用途による
   （§9 末尾）

### 残っている（semantic 不利）

6. **semantic は構造化オファー空間しか表現できない。** 自由文は送れない
7. ~~**実機で走らせているのは semantic だけ**~~ — 2026-08-19 に `compact_fec` も実機で
   測定し、同じバースト・同じ送信電力で一致を確認した（§4）

## 8. 残っている弱点

- **実機は 11〜14 dB を検証していない。** 到達範囲が −11.6〜+25.1 dB なので床（−60 dB）も
  天井（+40 dB）も測れず、正規化ができない。§4 が示したのは「DSP チェーンが両経路とも
  シミュレーションを再現する」ことであって、利得そのものは依然シミュレーションの結果
- **実機 15 エピソード vs シミュレーション 50 エピソードで、厳密な対エピソード比較ではない。**
  シードブロックは共有しているので最初の 15 は同一だが、集計は 50 件平均
- **n が小さい。** n=50 で 1 エピソード = 0.02、標準誤差は p≈0.5 で 0.07。
  §1 の正規化値の ±0.1 程度は意味を持たない。天井の点が 0.90〜0.98 に散らばっているのも
  これで、SNR 点ごとにシードブロックが違うため高 SNR 側の点同士も直接は比較できない
- **床が高い（semantic 0.48）ため、合意率単独では低 SNR 域の解像度が低い。** §9 のとおり
  −25 dB 以下は床と区別できない。オファー再現精度（§6）のほうが感度が高い
- **利得は単一タスク・単一モデル・単一 k での測定。** k=16 は semantic 側の設計値であり、
  compact_fec はそれに合わせている。k を変えたときに利得がどう動くかは未測定
- **LLM の生成温度 0.7 が固定されておらず、条件間で生成のばらつきが乗る。** 対シードは
  プールと値のみを固定する。天井の散らばりの一部はこれ

## 9. どこで壊れるか — 膝と「無情報の床」

`semantic` は −10 dB でもまだ 0.82 なので、崩壊点を見るためにグリッドを −30 dB まで延長した
（`results/sweep_lowsnr.json`、semantic 単独 50 エピソード。baseline は +5 dB 以下で既に
ちょうど 0.00 なので走らせていない）。

**そのまま読んではいけない。** `SemanticDecoder` は常に構造的に妥当なオファーを出力するので
（`pool_to_mask`）、チャネルが何も運んでいなくても合意率はゼロにならない。その値を測るのが
先決だった。

### 床の実測

`--snr-grid -60`（Shannon 等価 3×10⁻⁵ ビット/エピソード ＝ 実質ゼロ）で 50 エピソード:

```
無情報の床 = 合意率 0.48   社会厚生 47.3   Pareto 効率 0.74
```

**チャネルを完全に切っても合意率は 0.48 出る。** 両エージェントの事前分布が同じプールを見て
似たオファーを出すため、偶然一致する。この 0.48 を引かずに低 SNR の数字を読むと、
通信していないものを通信していると誤読する。

### 床に対する検定（n=50、両側 z）

| SNR | 合意率 | 床との差 | z | 床補正後 (p−0.48)/0.52 |
|---:|---:|---:|---:|---:|
| −30 | 0.56 | +0.08 | 0.8 | 0.15 |
| −25 | 0.40 | −0.08 | −0.8 | −0.15 |
| −20 | 0.70 | +0.22 | **2.3** | 0.42 |
| −15 | 0.74 | +0.26 | **2.8** | 0.50 |
| −10 | 0.82 | +0.34 | **3.8** | 0.65 |
| −5 | 0.94 | +0.46 | 5.9 | 0.88 |
| 0 | 1.00 | +0.52 | 7.4 | 1.00 |
| +20 | 0.98 | +0.50 | 6.8 | 0.96 |

**膝は −20 dB 付近。** −25 dB と −30 dB は |z| < 1 で床と区別がつかず、しかも SNR が上がると
値が下がる（0.40 → 0.56 が逆順）。これは通信が生きていれば起こらないので、
**−25 dB 以下では semantic パイプラインは何も伝えていない**と読むべき。

Shannon 等価ビットもこれを裏づける: −15 dB で 1 エピソードあたり **0.83 ビット**、
−30 dB で **0.03 ビット**。1 ビット未満で交渉が妥結するはずがない。

### 主張の書き直し

- ✅ **実際に通信できている下限は約 −20 dB。** そこから +0 dB まで、床補正後 0.44 → 1.04 と
  単調に改善する。これが「緩やかな劣化」の正しい範囲
- ✅ **§1 の実効 SNR 利得は影響を受けない。** 比較点の合意率 0.94（semantic −5 dB）は
  床から 5.9σ 離れており、事前分布では説明できない
- ❌ **「−30 dB でも 0.56」とは書かないこと。** 床が 0.48 なので何も言っていない

### 全パイプラインの床（−60 dB 実測、50 エピソード）

| | semantic | compact | compact_fec | raw / arq |
|---|---:|---:|---:|---:|
| 打ち切りあり | **0.48** | 0.02 | 0.06 | 0.00（構造上） |
| ターン数同一 | 0.48 | 0.08 | 0.10 | — |

同じ「通信の完全な失敗」でも**退化先が違う**:

- **semantic は事前分布に退化する** — 妥当なオファーを出し続け、たまたま合意する
- **デジタル側は拒否に退化する** — 復号失敗＝暗黙の REJECT

**どちらが良いかは用途による。**「壊れても妥当な既定値で動き続ける」ことが価値である応用
（制御、推薦）では semantic の退化が望ましく、「間違った合意を結ぶくらいなら黙るべき」応用
（決済、安全系）ではデジタル側の退化が正しい。§1 の正規化はこの差を除去しているので、
**除去してよいかは応用側の判断**であることを明記しておく。

### ⚠ ターン数の非対称性 — 測って潰した

[negotiation.py](../airComp/env/negotiation.py) は復号不能なメッセージが来た時点でエピソードを
打ち切る。`parse_offer` は全ての失敗を `None` に集約するので、**デジタル側は1エピソードにつき
実質1回しかチャンスがない**一方、`SemanticDecoder` は構造上 `None` を出せないため常に 10 ターン
使える。これは緩やかな劣化ではなく、環境が片方だけ早期終了させているだけ。

（証拠として、[prompts.py:47](../airComp/agents/prompts.py#L47) には
`"[message lost / unparseable]"` を履歴に描画する分岐があるが、打ち切り設計では到達不能な
デッドコードだった。当初はメッセージ損失を生き延びる設計だったことを示している。）

`NegotiationConfig.lost_message_ends_episode = False`（CLI は `--survive-lost-messages`）で
両者のターン数を揃えて再測定した結果:

| | −10 | −5 | 0 | +5 |
|---|---:|---:|---:|---:|
| compact_fec 生の合意率（打ち切りあり） | 0.02 | 0.16 | 0.46 | 0.78 |
| compact_fec 生の合意率（ターン数同一） | **0.20** | **0.30** | **0.66** | **0.84** |

**低 SNR で大きく改善する = 非対称性は実在した。** ただし床も 0.06 → 0.10 に上がるため、
正規化後の実効 SNR 利得は **16.6 → 14.3 dB**（正規化 0.5）、**11.5 → 11.4 dB**（0.9）。
**この交絡の値段は約 2 dB で、主張は生き残る。**

既定値は `True`（Phase 3 の結果を再現する）。公平比較の数字を引くときは `False` の側を使うこと。
