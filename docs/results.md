# Phase 3 の結果 — 崖 vs 緩やかな劣化

2026-08-18 実施。チェックポイント `checkpoints/jscc_dml.pt`（935 サンプル、final loss 0.2312）。

- シミュレーション: `results/sweep.json` — 3条件 × 7 SNR点 × 50 エピソード
- 低 SNR 延長: `results/sweep_lowsnr.json`（semantic のみ、−30〜−15 dB）と
  `results/sweep_floor.json`（−60 dB ＝ 無情報の床）。図用に統合したものが
  `results/sweep_extended.json`
- 実機: `hwlab/results/sdr_sweep.json` — HackRF One ×2 の導波路リンク、7点 × 15 エピソード
- 図: `results/agreement_rate_vs_snr.png` ほか2枚

## 1. 主結果

| SNR | raw 合意率 | arq 合意率 | semantic 合意率 | semantic 社会厚生 |
|---:|---:|---:|---:|---:|
| −10 | 0.00 | 0.00 | **0.82** | 81.9 |
| −5 | 0.00 | 0.00 | **0.94** | 94.7 |
| 0 | 0.00 | 0.00 | **1.00** | 100.6 |
| +5 | 0.00 | 0.00 | **0.96** | 96.2 |
| +10 | 0.28 | 0.10 | 1.00 | 101.2 |
| +15 | 0.94 | 0.82 | 1.00 | 99.5 |
| +20 | 0.92 | 0.86 | 0.98 | 99.4 |

⚠ 合意率は **0 から始まる指標ではない**。semantic の「無情報の床」は 0.48 で、
baseline は 0.00。低 SNR の数字は §9 の床と突き合わせて読むこと。

**ベースラインは −10 dB から +5 dB まで合意率ちょうど 0.00**、+10 dB で立ち上がり始め、+15 dB で
実用域に入る。semantic は全域で 0.82 以上、−5 dB 以上では 0.94 以上。

### 見出しの数字: 実効 SNR 利得 20〜25 dB

同じ合意率に達する SNR で比べる。

- 合意率 0.94: semantic **−5 dB** / raw **+15 dB** → **20 dB**
- 合意率 0.82: semantic **−10 dB** / arq **+15 dB** → **25 dB**

### 「崖 vs 緩やか」は確かに観測された

raw は +5 dB → +15 dB の 10 dB で 0.00 → 0.94 に跳ぶ。semantic は同じ区間で 0.96 → 1.00。
これが検証対象だった仮説そのもの。

なお **arq は raw より悪い**（+10 dB で 0.10 vs 0.28、+20 dB で 0.86 vs 0.92）。CRC が壊れた
メッセージを破棄する＝暗黙の REJECT になるため。raw は壊れていても運良く解釈できることがある。
「検出して捨てる」ほうが「壊れたまま渡す」より*タスク成果は悪い*というのは、この設定では
直感に反するが一貫した結果。

## 2. 利得の分解 — どこまでがチャネルの効果か

semantic の優位は3つの要因が混ざっている。分けないと過大主張になる。

1. アナログ潜在表現がビットより緩やかに劣化する（**主張したい効果**）
2. 受信側で JSON をパースしない（構造的な優位）
3. デコーダが実行可能なオファー空間に masked prior を持つ（構造的な優位）

2と3は「ノイズ耐性」ではなく**アーキテクチャの効果**なので、高 SNR での差がその上限を与える。

| SNR | semantic − raw | 解釈 |
|---:|---:|---|
| +20 dB | **+0.06** | チャネルがほぼ無損失 → これが 2+3 の寄与 |
| +15 dB | +0.06 | 同上 |
| +5 dB | **+0.96** | ほぼ全部がチャネル起因 |
| 0 dB | +1.00 | 同上 |

**アーキテクチャ由来は 0.06、チャネル由来は最大 0.94。** 主張の 94% はチャネルの効果で説明できる。
この分解を出さずに 0.96 という差だけを示すのは不誠実。

## 3. SNR の定義が両チャネルで一致していることの確認

これはフェアネスの根幹なので実測した。

```
digital BPSK: 実測 BER と教科書2種の照合
  SNR    実測      Q(sqrt(S))   Q(sqrt(2S))
   +0  1.59e-01    1.59e-01     7.86e-02
   +5  3.77e-02    3.77e-02     5.95e-03
  +10  7.82e-04    7.83e-04     3.87e-06

実数次元あたりの 信号電力/雑音電力:
  analog  公称 +10 dB -> 実測 +10.00 dB
  digital 公称 +10 dB -> 実測 +10.00 dB
```

**両チャネルとも「実数次元あたりの信号電力 / 雑音分散」が公称値どおり。** BPSK シンボルと潜在
ベクトルの各成分が同じ次元あたり SNR を受け取っており、比較は成立している。

⚠ **教科書の BPSK 曲線とは 3 dB ずれる。** 本実装の BER は `Q(sqrt(SNR))` で、教科書の
`Q(sqrt(2·Eb/N0))` ではない（雑音分散の取り方の違い）。査読者は必ず標準曲線と照合するので、
「ベースラインを不当に痛めつけている」と誤解される前にこれを明示すること。両チャネルで
同一の定義を使っている以上、比較の公平性は損なわれていない。

崖の位置もこれで説明がつく: +10 dB で BER 7.8e-4、1メッセージ約650ビット →
無傷な確率 (1−7.8e-4)^650 ≈ 0.60、1エピソードに約2メッセージ必要 → 0.36。実測 0.28 と整合。

## 4. 実機とシミュレーションの一致 — DSP チェーンの検証

対シード設計（`int(snr_db*10_000) + 1_000_000` が両者で一致）なので、系統的なズレがあれば
物理現象ではなくバグ。

| 要求 SNR | 実測 SNR | sim 合意率 | 実機 合意率 | 差 |
|---:|---:|---:|---:|---:|
| −10 | −9.59 | 0.82 | 0.87 | +0.05 |
| −5 | −4.33 | 0.94 | 1.00 | +0.06 |
| 0 | −0.67 | 1.00 | 1.00 | 0.00 |
| +5 | **+6.36** | 0.96 | 1.00 | +0.04 |
| +10 | +9.83 | 1.00 | 1.00 | 0.00 |
| +15 | +14.70 | 1.00 | 0.93 | −0.07 |
| +20 | +20.32 | 0.98 | 1.00 | +0.02 |

**系統的なズレは無い。** 平均差 +0.014、最大 |差| 0.07。実機は 15 エピソードなので
1 エピソード = 0.067 であり、**すべてのズレが1エピソード以内**。DSP チェーン
（RRC 整形、IF オフセット、ZC プリアンブル、パイロット、ゼロフォーシング等化、SNR 推定）は
シミュレーションのアナログチャネルを正しく再現している。

バースト欠落率は全点 **0%**、RX 警告ゼロ、リトライ 0%。

⚠ **+5 dB 点だけ要求と実測が 1.36 dB ずれており、1 dB 基準を外している**（他6点は 0.17〜0.67 dB）。
較正テーブルの粒度による。図では実測 SNR の位置に描いてあるので結論には影響しないが、
較正点を増やせば解消する。

## 5. 帯域の公平性

ビット数だけを根拠に帯域の主張をしないこと（CLAUDE.md の指示）。3つの見方を併記する。

### (a) 生のペイロード

| | 1メッセージあたり | 1エピソードあたり |
|---|---|---|
| baseline (raw) | UTF-8 JSON 約 650〜1350 ビット | 1165〜2693 ビット |
| semantic | **実数シンボル 16 個**（k=16） | 32 シンボル（平均2メッセージ） |

ベースラインのペイロードが SNR で変わるのは、低 SNR では合意に至らず早期終了してターン数が
減るため。ターン数が条件間で異なるので、エピソード単位の比較は目安にとどめること。

### (b) Shannon 等価ビット（`k · 0.5·log2(1+SNR)`）

| SNR | −10 | −5 | 0 | +5 | +10 | +15 | +20 |
|---|---:|---:|---:|---:|---:|---:|---:|
| semantic 等価ビット/エピソード | 2.4 | 6.3 | 16.0 | 32.9 | 55.4 | 80.4 | 106.5 |

**+5 dB では semantic は等価 32.9 ビットで合意率 0.96、ベースラインは 1313 ビットで 0.00。**
情報量あたりで約 40 倍の差があり、semantic が帯域を多く使って勝っているのではない。

### (c) 実機の物理コスト（ここは semantic に不利）

```
data_symbols: 8   overhead_symbols: 863   total: 871   (99.1% がオーバーヘッド)
内訳: プリアンブル 511 + パイロット 32 + ガード 320
burst_duration: 8.71 ms   occupied_bandwidth: 135 kHz
```

同期のためのフレーミングコストで、JSCC の主張とは独立。ペイロードを長くすれば償却されるが、
**現状の 16 実数という極端に短いペイロードでは、物理層コストがペイロードを2桁上回る。**
「16 シンボルで済む」という主張をするときは、この 871 シンボルを併記しないと誤解を生む。

## 6. デコーダは本当にチャネルを使っているか

タスク指標が平坦なとき、「頑健」と「入力を無視して事前分布を出している」は区別がつかない。
`python evaluate.py decoder-check --checkpoint checkpoints/jscc_dml.pt --dataset data/jscc_dataset_dml.pt`

```
      条件      完全一致  項目別  アクション
 ノイズ無し       0.826   0.917   1.000
  SNR -10 dB      0.646   0.766   0.815
  SNR +20 dB      0.832   0.917   1.000
 純ノイズ         0.365   0.475   0.463
 ゼロ入力         0.495   0.553   0.501
 最頻値の定数     0.525   0.553      -

PASS: 信号 0.836 / ノイズ・ゼロ床 0.495 / 最頻値定数 0.525
```

**デコーダは確かにチャネル出力を使っている。** さらにオファー再現のレベルでは
**きちんと劣化している**（+20 dB で 0.832 → −10 dB で 0.646、アクション精度 1.000 → 0.815）。

つまり平坦なのは通信が完璧だからではなく、**交渉タスクが 20〜25% のオファー誤りを吸収する**から。
「緩やかな劣化」を主張するときは、タスク指標だけでなくこの再現精度を併記すること。

⚠ この診断は学習データ 935 件で測っているので絶対値は楽観的。ただし同じデータで純ノイズが
0.365 に落ちる以上、入力依存性の結論は変わらない。

## 7. 明示しておくべき非対称性

CLAUDE.md の方針（情報量の非対称は文書化するか対称化する）に従い、semantic 側に有利な点を列挙する。

1. **デコーダは実行可能オファーの masked prior を持つ**（`pool_to_mask`）。プールを超える個数は
   構造的に出力できない。ベースラインは文字列を復元しなければならない
2. **送信側 JSON がパース不能でも semantic は動く。** 隠れ状態は生成さえされればプールできる。
   ベースラインは生成と*パース可能性*の両方を要求される。これは実質的な優位であり、
   §2 の高 SNR 差 0.06 に含まれている
3. **semantic は構造化オファー空間しか表現できない。** 自由文は送れない。これは逆に semantic 側の
   制約であり、比較を semantic 有利にしすぎない方向に働く
4. **失敗したときの退化先が違う。** semantic は事前分布（合意率 0.48）に、baseline は拒否
   （0.00）に退化する。これが最大の非対称性で、§9 で定量した

## 8. 残っている弱点

- **実機 15 エピソード vs シミュレーション 50 エピソードで、厳密な対エピソード比較にはなっていない。**
  シードブロックは共有しているので最初の 15 は同一だが、集計は 50 件平均。厳密化するには
  シミュレーションを 15 エピソードで回し直すか、エピソード単位の記録を保存する必要がある
- **n が小さい。** 実機 15 では 1 エピソード = 0.067。合意率 0.93 と 1.00 の差は 1 エピソード
- **床が高い（0.48）ため、合意率単独では低 SNR 域の解像度が低い。** §9 のとおり −25 dB 以下は
  床と区別できない。オファー再現精度（§6）のほうが低 SNR では感度が高いので、
  今後の低 SNR 実験はそちらを主指標にすべき
- **床の測定が semantic 側にしかない。** baseline の床は「パース不能＝REJECT＝0.00」と
  構造から自明なので測っていないが、厳密には同じ扱いをすべき

## 9. どこで壊れるか — 膝と「無情報の床」

`semantic` は −10 dB でもまだ 0.82 なので、崩壊点を見るためにグリッドを −30 dB まで延長した
（`results/sweep_lowsnr.json`、semantic 単独 50 エピソード。baseline は +5 dB 以下で既に
ちょうど 0.00 なので走らせていない）。

**そのまま読んではいけない。** `SemanticDecoder` は常に構造的に妥当なオファーを出力するので
（`pool_to_mask`）、チャネルが何も運んでいなくても合意率はゼロにならない。その値を測るのが
先決だった。

### 床の実測

`--snr-grid -60`（Shannon 等価 3×10⁻⁵ ビット/エピソード ＝ 実質ゼロ）で 50 エピソード:

```
無情報の床 = 合意率 0.48   社会厚生 47.3   Pareto 効率 0.74
```

**チャネルを完全に切っても合意率は 0.48 出る。** 両エージェントの事前分布が同じプールを見て
似たオファーを出すため、偶然一致する。この 0.48 を引かずに低 SNR の数字を読むと、
通信していないものを通信していると誤読する。

### 床に対する検定（n=50、両側 z）

| SNR | 合意率 | 床との差 | z | 床補正後 (p−0.48)/0.52 |
|---:|---:|---:|---:|---:|
| −30 | 0.56 | +0.08 | 0.8 | 0.15 |
| −25 | 0.40 | −0.08 | −0.8 | −0.15 |
| −20 | 0.70 | +0.22 | **2.3** | 0.42 |
| −15 | 0.74 | +0.26 | **2.8** | 0.50 |
| −10 | 0.82 | +0.34 | **3.8** | 0.65 |
| −5 | 0.94 | +0.46 | 5.9 | 0.88 |
| 0 | 1.00 | +0.52 | 7.4 | 1.00 |
| +20 | 0.98 | +0.50 | 6.8 | 0.96 |

**膝は −20 dB 付近。** −25 dB と −30 dB は |z| < 1 で床と区別がつかず、しかも SNR が上がると
値が下がる（0.40 → 0.56 が逆順）。これは通信が生きていれば起こらないので、
**−25 dB 以下では semantic パイプラインは何も伝えていない**と読むべき。

Shannon 等価ビットもこれを裏づける: −15 dB で 1 エピソードあたり **0.83 ビット**、
−30 dB で **0.03 ビット**。1 ビット未満で交渉が妥結するはずがない。

### 主張の書き直し

- ✅ **実際に通信できている下限は約 −20 dB。** そこから +0 dB まで、床補正後 0.42 → 1.00 と
  単調に改善する。これが「緩やかな劣化」の正しい範囲
- ✅ **§1 の実効 SNR 利得 20 dB は影響を受けない。** 比較点の合意率 0.94（semantic −5 dB）は
  床から 5.9σ 離れており、事前分布では説明できない
- ❌ **「−30 dB でも 0.56」とは書かないこと。** 床が 0.48 なので何も言っていない

### ⚠ これ自体が非対称性である

床が semantic は 0.48、baseline は 0.00。同じ「通信の完全な失敗」でも、

- **semantic は事前分布に退化する** — 妥当なオファーを出し続け、たまたま合意する
- **baseline は拒否に退化する** — パース不能＝暗黙の REJECT で、合意率はちょうど 0.00

これは実装の都合ではなく設計の帰結で、**どちらが良いかは用途による**。「壊れても妥当な既定値で
動き続ける」ことが価値である応用（制御、推薦）では semantic の退化のほうが望ましく、
「間違った合意を結ぶくらいなら黙るべき」応用（決済、安全系）では baseline の退化のほうが正しい。
§2 の分解と同様、**この差はチャネルのノイズ耐性ではない**ので、利得として計上してはいけない。
図では床を点線で示している。
